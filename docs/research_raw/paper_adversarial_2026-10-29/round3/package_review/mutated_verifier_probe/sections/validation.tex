\section{Infrastructure, artifact validation and exact-prefix audits}
\label{sec:validation}

\subsection{A reconstructible record of decisions and consequences}

MonopolyBench separates the engine, orchestration harness, telemetry and render-only interface. The engine emits authoritative states, decisions and events. The harness constructs model-facing payloads, sends requests through OpenRouter and resolves returned attempts. Telemetry preserves applied actions, prompt/response artifacts, attempt indexes, validation errors, usage records and event ranges. This separation makes it possible to ask both what the system did and what information was available when it did so. It does not make every derived summary reliable by construction.

Independent event reductions reconcile the cohort's economic record. All 6,989 initial decision payloads agree with reconstructed cash, ownership, development and bank stock. All 10,235 saved state snapshots match an event-folded economic state at a corresponding boundary, and terminal states reconcile in all twenty games. The 113 accepted trades match cash, deed and transfer-interest flows derived from the final accepted terms, including \$431 in interest across thirty settlements. Jail-card transfers require transaction or bankruptcy context because they do not have dedicated transfer events; the reconstructed holdings nevertheless match all 27,956 player observations. This is a schema limitation, rather than evidence that the transfers did not occur.

The complete applied action streams replay in all twenty games after the documented canonicalization. Memory reconstructed from events matches all 6,989 recorded initial memory windows. A separate branch test restores one recorded mid-game prefix in each game, spanning purchase, management, auction, jail and trade-response decisions. At these twenty prefixes, the pending decision identifier and rebuilt memory match, the recorded action reproduces the next events, and a different legal action produces a divergent continuation. Matching subsequent stochastic events tests more than a public snapshot: the replay also restores the relevant hidden random and deck state.

The separate twenty-prefix test and the 126-case certificate audit establish their stated branches and the recorded memory checks, not full prompt equality at every possible branch or a new LLM-controlled suffix experiment. Longer reference-policy continuations terminate by bankruptcy in nineteen of twenty tested branches. The remaining branch is truncated after 20,000 decisions with two surviving cash-accumulating players. The twenty uncapped LLM games' termination is therefore an observed outcome, not a termination guarantee. Training or rollout experiments need an explicit horizon and truncation rule.

\subsection{Observation and resolution defects discovered by auditing}

Validation also identifies discrepancies between canonical events and the summaries presented to agents. A single trade-history formatting assumption treats the original initiator as the current terms' author. It reverses giving directions in forty-four of 113 accepted-trade summaries---the same forty-four settlements whose final author differs from the initiator in Section~\ref{sec:sol-economic-results}---misattributes twenty-six of 413 rejected offers, and produces self-partner wording in 232 of 394 counters. At least one of these manifestations appears in 2,054 of 6,989 initial prompts. The three counts describe one formatter assumption on different surfaces, not three independent defects. Structured holdings and cash remain correct, and in-thread trade history provides additional information. G14 d140 records transaction-specific recognition of a reversed summary. That recovery is a counterexample to inevitable reliance, not proof that all affected reasoning was repaired.

Public-message delivery also differs from canonical logging. Of 6,882 nonempty canonical public utterance occurrences, 149 never enter the timeline: ninety-four are omitted when consecutive building summaries retain an earlier nonempty message, and fifty-five are consumed by a bankruptcy cash event without a timeline summary. Of 6,733 inserted occurrences, 6,720 are observed in at least one opponent's later timeline. The other thirteen have no observed opponent timeline delivery before the record ends. These are occurrence-level channel facts. Repetition, private notes and other prompt fields prevent equating timeline omission with total semantic nonexposure.

The received-response audit identifies 139 selected Grok action-name conflicts: 138 top-level JSON-name comparisons and one separately recorded malformed-content case. Fifteen have equal parsed argument objects; only five have literally identical argument substrings. Reading all attempts instead of selected ones adds nine discarded JSON-name conflicts, explaining an earlier count of 147 strict-JSON conflicts versus 139 selected conflicts. This reconciliation is by case identity, not approximate totals.

All 139 selected disagreements already appear in the saved nonstreamed JSON response bodies received from OpenRouter, whose content and tool names match the canonical attempt records. This excludes local streaming assembly for these checked name conflicts. It does not distinguish generation, provider processing or gateway behavior. The applied name follows the received tool. Sol and Gemini's selected content fields are empty, so absence of this detectable form in their records cannot support a comparative consistency score. Nor does a name disagreement identify which channel expresses a stable intention.

Refusal recovery changes subsequent context as well as the current action. In 1,108 of 1,696 Opus decisions, private memory is empty; in another 286 it contains only literal synthetic fallback notes. Thus 1,394 decisions lack a model-authored private note in that memory window. The sixty-one defaulted construction plans discussed above also feed synthetic notes into later context. The observed configured-agent trajectory includes this interaction among response policy, validation and memory. The corpus does not isolate the effect of restoring notes, changing retry budgets or repairing history text.

\subsection{What the environment currently supports}

The implementation provides deterministic transitions, legal menus, persisted attempts and state, recovery, reference policies and composed exact-prefix continuation. This study measures artifact agreement and exercises these components for local alternative-action audits. It does not train a policy, expose a packaged reinforcement-learning adapter or validate a reward interface. Nor does it establish that fixing one observed defect improves long-horizon outcomes. Those are distinct experiments requiring new runs.

The engine and all twenty saved games are already publicly tracked at \url{https://github.com/KushagraBharti/MonopolyBench}, under the repository's Apache-2.0 license. The inspected remote commit is \texttt{1133b6b839162ec4929dd80b1a6a2397e2422616}; its tree contains events, actions, decisions, snapshots and per-attempt artifacts for the cohort. This is an availability check, not independent verification of every released field. The present manuscript revision and certificate bundle are new local research outputs, not files claimed to be in that public commit.

The accompanying portable certificate bundle reproduces the 126-case census without access to the repository checkout after dependency installation. It was executed in a fresh isolated environment, and a separate reviewer checked the original population, copied engine, witnesses and event hashes. That is stronger than regenerating a figure from aggregate data, but it is not an external team's independent scientific replication. Appendix~\ref{app:certificates} states the commands, certificate limits and review provenance.
