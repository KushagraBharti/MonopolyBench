# Claude round 1: independent findings and plan sketch

## Findings (verified in code or data)

1. One active run per API process. `RunManager` (python/apps/api/src/monopoly_api/run_manager.py) holds one `_runner`, `_run_id`, `_snapshot`. `start_run` stops any running game before starting a new one (`if self._is_running(): await self._stop_run_locked()`). `/run/stop`, `/run/pause`, `/run/resume`, `/run/status`, and `/ws` take no run id. Five tabs pressing play today means each start kills the previous game.
2. The OpenRouter client is async httpx (`openrouter_client.py`), default `timeout_s=30`, `max_retries=2`, non-streaming unless a stream callback is set (RunManager never sets one). Many past calls took longer than 30 s without errors, so the 30 s value is a per-read timeout, not a total deadline. One call in frontier-166 recorded latency 44,124 s (12.3 h), which looks like a laptop sleep or a hung socket. There is no total wall-clock deadline per request.
3. Recovery exists only in the API path. `RunManager.recover_run` rebuilds a runner from `run_config.json`, `events.jsonl`, `actions.jsonl` (`resume_actions`, `resume_events`). The campaign runner (`long_campaign._run_campaign_row`) refuses a non-empty, incomplete run dir and marks the cell failed. Nothing auto-recovers on process start.
4. `append_jsonl` opens, writes, closes, with no fsync. A hard crash can leave a partial last line, and recovery reads the files with plain JSON parsing.
5. A run writes to two trees: `runs/<run_id>/` and `quality_check/<run_id>/` (quality root is `runs_dir.parent / "quality_check"`, run_files.py `build_run_files`). Saved games add `analysis/` and a zip.
6. Real sizes (saved_games/frontier-*): 3,128 to 7,406 files per game; 58 to 167 MB per saved game; frontier-191 is run/ 70 MB (decisions.jsonl alone 30 MB, prompts/ 21 MB with 3,020 files, state/ 6.1 MB with 775 snapshots), quality_check/ 17 MB (1,208 files), analysis/ 24 MB. Five games are roughly 0.3 to 0.85 GB. A 48-game campaign is roughly 3 to 8 GB.
7. Past frontier games (medium effort, Opus 4.8, Gemini 3.1 Pro, Grok 4.3, GPT-5.5): 115 to 191 turns, 371 to 631 attempts, 1.6M to 2.9M prompt tokens and 0.28M to 0.64M completion tokens. Actual cost $12.06 to $27.71. Median call latency 9 to 12 s; GPT-5.5 median 13 to 38 s; p95 38 to 81 s. Summed call latency per game 1.3 to 3.9 h (excluding the 12 h outlier). Calls are sequential within a game, so wall time per game is about the summed latency.
8. Projected cost with the new models, reusing past token counts per lab: if GPT-6.1 Sol is $10/$50 (the user's table), $16 to $39 per game, mean $29, 5 games about $144, 48 games about $1,390. If it is $2/$10 (OpenRouter's listing on 2026-10-24 for provider `openai`), $7.50 to $15.80 per game, mean $11.40, 5 games about $57, 48 games about $550. Higher reasoning effort raises completion tokens, so treat these as medium-effort floors.
9. OpenRouter catalog check (public /api/v1/models and /endpoints, 2026-10-24): all four IDs exist and support tools, tool_choice, reasoning, reasoning_effort. Opus 5.5 $4/$20 (anthropic). GPT-6.1 Sol $2/$10 on `openai`, with tiers `openai/flex` $1/$5, `openai/fast` $4/$20, `openai/ultrafast` $12/$60, and >272K-prompt override $4/$15. $10/$50 matches `openai/gpt-6-astra`, not 6.1 Sol. Gemini 4 Argon $2/$10 on `google-ai-studio`, plus `/flex` $1/$5 and `/priority` $3.60/$18. Grok 4.7 $2/$6 on `xai` and `xai/zdr`, plus `/priority` $4/$12. OpenRouter docs: a base slug matches all variants and regions but not service-tier endpoints; pin a full slug for one exact endpoint.
10. `DEFAULT_PROVIDER_BY_MODEL_ID` and `players.json` only know the older models. `ALLOWED_REASONING_EFFORT = {"low","medium","high"}`; OpenRouter accepts none, minimal, low, medium, high, xhigh, max. ## Plan sketch

Hosting: one VM with an attached volume (Hetzner-class, 4 vCPU / 8 GB, price to verify after Hetzner's 2026 increases), Docker Compose. FastAPI serves the built frontend, API, and per-run WebSockets. A scheduler service runs queued games with max concurrency 5, one worker process per game. SQLite (WAL) on the volume holds the game index and job queue. Artifacts stay on the volume in the exact local layout. Cloudflare Tunnel plus Cloudflare Access for HTTPS and login, or Tailscale if no domain. Off-box copy to Cloudflare R2 (no egress fees) on game completion plus periodic in-progress sync. Infra cost is $10 to $40 a month against $57 to $144 of OpenRouter spend per 5 games, so choose infra for reliability.

Not chosen: Vercel or Netlify functions (multi-hour games and WebSockets do not fit function time limits); Supabase or Neon (the data is files, the index is small, and a remote DB adds a failure point); Railway or Render (workable, but auto-redeploy restarts in-flight games and 24/7 compute plus volume costs more; keep as the managed fallback).

Process model: job table with statuses queued, starting, running, finalizing, completed, failed, interrupted, stopped, budget_stopped. Worker heartbeats every 15 s. The scheduler reconciles on boot and every few seconds: dead worker with stale heartbeat becomes interrupted, then auto-resume through the existing action-replay recovery, capped at N attempts. Resume must replay recorded actions, check replayed events against recorded events, keep orphaned attempt artifacts from the in-flight decision, and log a recovery record in the run dir. Each run records git SHA, lock hash, prompt and tool hashes; resume refuses a different SHA. Deploys drain or refuse while games run.

Live view: the API tails each run's `events.jsonl` and latest `state/` snapshot and serves `/ws/runs/{run_id}` with the existing HELLO, SNAPSHOT, EVENT envelope. Keep legacy `/ws` for local use.

Safety: dedicated OpenRouter key with a credit limit; per-game cost cap; campaign cap through existing `should_stop_for_budget`; credit gate before each start; total request deadline and stall alert; ntfy or webhook notifications on complete, fail, stall.

Export: per-run zip (run tree + quality_check tree + export manifest with per-file SHA-256 and the saved-game tree hash) from the dashboard; bulk `scripts/pull_cloud_runs.sh` with rsync over SSH/Tailscale or rclone from R2 into local `runs/` and `quality_check/`; local hash verification; then the existing standardize and analyze scripts.

Dashboard: All games grid modeled on the screenshot (board thumbnail, status, roster chips, turn, cost, elapsed, winner), tabs for Active, Completed, Archived, header aggregates, Create game 3-step modal (players and seats, settings incl. reasoning effort, number of games and seat rotation, review with server-side cost estimate and budget cap). Campaign mode makes settings read-only from the frozen contract. UI stays render-only.

Research integrity: paper-eligible games run as cells of a new tested campaign contract (new roster entry, seeds, rotations, effort, routes, ceiling). Ad-hoc dashboard games are labeled exploratory. The user must record approval for spending and for any change to allowed effort levels.

Verification: zero-cost full games with scripted baseline actors x5 concurrently on the server; kill -9 a worker mid-game and confirm resume plus replay pass; reboot the VM mid-batch; export round trip with hash match; one short paid smoke game; then the first 5-game batch.

## Addendum: recovery details checked in code

14. `LlmRunner._restore_interrupted_run` (llm_runner.py:141) replays every recorded action through the engine, checks that replayed canonical event lines equal the recorded events, rebuilds prompt memory from events, and resumes at the pending decision. This keeps engine determinism. Tests: apps/api/tests/test_llm_runner.py:41 (private thought survives recovery) and test_run_manager_idempotency.py:160.
15. Gap: prompt files for attempt 0 are named `decision_<id>_{system,user,tools,response,parsed}` (run_files.py:368 `_prompt_file_prefix`) and are written with `write_text`. If the process dies after an attempt for the pending decision was sent (and possibly billed) but before its action was recorded, the post-recovery attempt overwrites those files, and the same happens in quality_check/. That breaks "never overwrite" and loses evidence of a billed attempt. Fix before cloud use: move or suffix the orphaned files (e.g. `prompts/interrupted/r<k>/`) and write a recovery record listing them and any orphan `usage_attempts` rows.
16. scripts/research/prove_prompt_reconstruction.py exists and can check that the first post-recovery prompt equals what an uninterrupted run would send. Use it in the recovery test.

20. Cloudflare R2 (third-party summaries, verify): $0.015/GB-month, Class A $4.50/M, Class B $0.36/M, egress $0, free 10 GB + 1M A + 10M B per month.

Revised view: the workload is I/O-bound (each game makes one LLM call at a time). Five games likely need under 2 GB RAM and a fraction of a vCPU. Usage-billed Railway Pro (about $20/mo, 50 GB volume) may now cost the same as or less than a Hetzner VM and is faster to set up. The cost is that every deploy interrupts games, so automatic, hardened recovery is mandatory either way. Auth would be in-app (Railway has no access gate; a public *.up.railway.app origin bypasses Cloudflare Access unless the app checks the Access JWT).
